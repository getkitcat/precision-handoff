01

Provision your own accounts

High

None of the services below convey with the source. Each must be created, verified, and billed under your own organization before anything else can proceed.

P01Accounts checklist
  • GitHub account/org to hold the private repository (126 pages of source).
  • Cloudflare account with Pages, Workers, and DNS enabled.
  • Domain registrar access for precisionplumbingpros.com (transfer inbound — see P05).
  • Web3Forms account for a new form access key.
  • Google Search Console + GA4 property, re-verified under your own Google account.
  • Google Business Profile management access (for local ranking continuity).
If skipped

The site remains dependent on KitCat accounts you do not control and cannot administer, bill, or secure.

02

Local build environment

Medium

The npm run build command compiles the source into a dist/ folder on a developer machine. It does not deploy, host, or configure anything. Building is step one of many.

P02Toolchain
  • Install Node.js 18+ and npm.
  • Run npm install — pulls ~344 MB of dependencies incl. the native sharp image binary (platform-specific; fails silently on the wrong architecture).
  • Run npm run build → outputs dist/ (~41 MB, 126 pages).
  • Run npm run preview to smoke-test locally before any deploy.
Gotcha

A build that "succeeds" locally can still ship broken image derivatives if sharp resolves to the wrong binary in CI. Verify the built output, not just the exit code.

03

Repository & deploy pipeline

High

Cloudflare Pages builds from a connected Git branch. The build settings are non-default and must match exactly, or the deploy 404s or serves stale routes.

P03Cloudflare Pages project
  • Push the source into your own GitHub repo (main branch).
  • Create a Pages project bound to that repo.
  • Build command: npm run build · Output directory: dist.
  • Set NODE_VERSION build env to 18+ or the build fails on Astro 5.
  • Confirm the first deploy renders all 126 routes, not just the homepage.
Critical

Trailing-slash config. This site depends on trailingSlash:'always' plus canonical/internal-link normalization. Get it wrong and Google reads every URL as a duplicate and deindexes the site — this exact failure has taken KitCat Astro sites from fully-indexed to parked. There is no error message; you find out via lost traffic weeks later.

04

Domain & DNS cutover

Critical

Live production domain. Every step here is customer-facing the moment it propagates.

P04Cutover sequence
  • Complete the inbound domain transfer / nameserver change to your Cloudflare.
  • Recreate all DNS records (apex + www + any mail/verification TXT).
  • Bind the domain to the Pages project; wait for SSL certificate issuance.
  • Re-implement the www → apex 301 redirect (currently a KitCat rule).
  • Verify HTTPS, redirects, and propagation across regions before announcing.
If mistimed

Pointing DNS before SSL issues, or dropping a verification TXT record, takes the live site — and every "call now" phone path on it — offline during propagation. Rollback can take up to 24–48h to propagate back.

05

Rehost the blog CMS (Sveltia)

Critical

The /admin editor is a GitHub-backed headless CMS. Its authentication currently routes through a Cloudflare Worker on KitCat's account (sveltia-cms-auth.getkitcat.workers.dev). This is the single most involved part of the migration and there is no hosted fallback — you must rebuild the auth layer from scratch.

P05CMS auth rebuild
  • Register a new GitHub OAuth App → obtain client ID + client secret.
  • Deploy your own sveltia-cms-auth Cloudflare Worker.
  • Set the OAuth CLIENT_ID / CLIENT_SECRET as Worker secrets.
  • Edit public/admin/config.yml: repoint repo: to your GitHub repo and base_url: to your new Worker.
  • Grant the Worker/OAuth app write access to the repo; test a live login + publish round-trip.
Until done

The blog editor at /admin is completely locked out — anyone attempting to log in authenticates against KitCat's worker and is rejected. Your team cannot publish or edit a single blog post until this is rebuilt correctly.

06

Lead capture / forms

Critical

Every contact and quote form submits to the Web3Forms API using an access key tied to KitCat's Web3Forms account.

P06Form backend swap
  • Create your own Web3Forms account + access key.
  • Replace the key everywhere it appears in the source (landing pages + service page forms).
  • Point delivery at your own inbox; send a live end-to-end test submission.
  • Confirm spam/honeypot + success-redirect behavior still works.
If skipped

Every lead is silently lost. Forms will appear to submit successfully while the notifications route to KitCat's account, not yours. No error, no bounce — you simply stop receiving customers and don't know why.

07

SEO / GEO integrity

High

The site's ranking depends on machine-readable plumbing that must survive the move intact. This is invisible on-screen and easy to break.

P07Search-integrity checklist
  • Preserve the auto-generated sitemap-index.xml and confirm it lists all live URLs.
  • Preserve canonical tags + trailing-slash normalization (see P03).
  • Keep the JSON-LD schema, robots.txt, and llms.txt blocks intact.
  • Re-verify the domain in Google Search Console under your account; resubmit the sitemap.
  • Re-map any existing redirects so no indexed URL 404s post-cutover.
If mishandled

25+ years of local reputation are anchored to these rankings. A botched canonical or lost redirect map can drop the site out of Google's index for weeks — during which competitors take the calls.

08

Analytics & ongoing ownership

Medium

Migration is not the end — a live site is a standing maintenance obligation.

P08Tracking + maintenance
  • Re-provision GA4 / GTM / Cloudflare Zaraz tags under your own accounts.
  • Own dependency + security updates (Astro majors, sharp, wrangler) going forward.
  • Own every future content change, redeploy, and uptime/rollback response.
  • Maintain your own source backups — KitCat's copy is not a support contract.
Reality

Once transferred, no part of this system is monitored, patched, or supported by KitCat. A broken deploy at 5pm on a Friday is entirely yours.
